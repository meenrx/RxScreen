# RxScreen — QR Payload Spec (HOSxP OPD sticker)

QR ที่พิมพ์บนฉลากยา OPD (รพ.รือเสาะ) ส่งข้อมูลคนไข้ให้ RxScreen สแกนคัดกรอง
Parser ฝั่ง RxScreen: `src/features/screening/QrScanner.tsx` → `parseKeyedFields()`

## รูปแบบรวม
```
N<hn>|R:<icodes>|A<age>|S<sex>|W<kg>|Gf<gfr>[stage]@YYMMDD|I<inr>@YYMMDD|K<k>@YYMMDD|Y<n>:<allergens>|D:<icd10>|P|O<ast>@YYMMDD|L<alt>@YYMMDD|G<fbs>@YYMMDD|A1<a1c>@YYMMDD|Nc<anc>@YYMMDD|Ec<aec>@YYMMDD
```
- **คั่นแต่ละฟิลด์ด้วย `|`** — parser split ด้วย `|` แล้วจับ **key ด้วย prefix** (ไม่อิงตำแหน่ง → สลับลำดับได้)
- **แลปทุกตัว = `<ค่า>@YYMMDD`** โดย `YYMMDD` = วันตรวจ (ค.ศ. 2 หลัก เช่น `260421` = 21 เม.ย. 2026)
- **ฟิลด์ที่ไม่มีข้อมูล/ไม่เข้าเกณฑ์ = ไม่ส่งมาเลย** (ไม่ใช่ค่าว่าง) → parser เจอเท่าที่มี

## ตารางฟิลด์ทั้งหมด

| Key | ความหมาย | เก็บใน (ScannedData) | รูปแบบค่า | แสดงเมื่อ |
|-----|----------|----------------------|-----------|-----------|
| `N` | HN คนไข้ (คีย์หลัก) | `hn`, `an` | ตัวเลข HN | เสมอ |
| `R:` | รายการยา visit นี้ | `drugs[].icode` | `icode,icode,...` | มียา (**ตัดยาฉีด IV + irrigation ออก**) |
| `A` | อายุ (ปี) | `age` | จำนวนเต็ม | เสมอ |
| `S` | เพศ | `sex` | `M` / `F` | เสมอ |
| `W` | น้ำหนัก (กก.) | `weight` | จำนวนเต็ม | มีชั่งน้ำหนัก visit นั้น |
| `Gf` | eGFR + ระยะ CKD | `gfr`, `ckd_stage`, `labs.gfr` | `<ค่า>[stage]@YYMMDD` เช่น `47[3]@260105` | มีผล eGFR |
| `I` | INR | `inr` | `<ค่า>@YYMMDD` | **เฉพาะคนได้ warfarin** |
| `K` | โพแทสเซียม | `labs.k` | `<ค่า>@YYMMDD` | **เฉพาะเมื่อ K<3.5 / K>5 / ได้ ACEI-ARB-spiro-digoxin** |
| `O` | **AST (SGOT)** | `labs.ast` | `<เต็ม>@YYMMDD` | **เฉพาะมียาพิษต่อตับ** (statin/anti-TB/valproate/azole/ARV...) |
| `L` | **ALT (SGPT)** | `labs.alt` | `<เต็ม>@YYMMDD` | เหมือน O |
| `G` | **FBS (น้ำตาลอดอาหาร)** | `labs.fbs` | `<เต็ม>@YYMMDD` | **เฉพาะมียาเบาหวาน** |
| `A1` | **HbA1c** | `labs.hba1c` | `<ค่ามีจุดทศนิยม>@YYMMDD` เช่น `A17.2` = 7.2% | **เฉพาะมียาเบาหวาน** |
| `Nc` | **ANC (นิวโทรฟิลสัมบูรณ์)** | `labs.anc` | `<เต็ม>@YYMMDD` | **เฉพาะมียากดไขกระดูก** (methimazole/colchicine/MTX...) |
| `Ec` | **AEC (อีโอซิโนฟิลสัมบูรณ์)** | `labs.aec` | `<เต็ม>@YYMMDD` | **เฉพาะมียาเสี่ยง DRESS** (allopurinol/cotrimoxazole...) |
| `Y` | แพ้ยา | `allergies[]` | `<จำนวน>:<ตัวย่อ6ตัว,..สูงสุด4>` เช่น `Y2:IBUPRO,ROXITH` | มีประวัติแพ้ |
| `D:` | วินิจฉัย (ICD10) | `diseases[]` | `icd10,icd10,...` | มี dx visit นั้น |
| `P` | ตั้งครรภ์/ให้นม | `is_pregnant=true`, `is_lactating=true` | (มี key = จริง) | ICD10 = O*/Z32-39 หรือ opdscreen.pregnancy=Y |

## กฎการ parse ที่ต้องรู้ (มีในโค้ดแล้ว)
1. **HbA1c (`A1`) ต้องมีจุดทศนิยม** — regex `^A1(\d*\.\d+)` เพื่อ**กันชนกับอายุ** (`A16` = อายุ 16 ไม่ใช่ HbA1c) → QR ส่ง `round(x,1)` ให้มี `.0` เสมอ
2. **เรียง key ยาว→สั้น** ใน `KEYS` — `Gf` มาก่อน `G`, `Nc` ก่อน `N`, `A1` จับแยกก่อน `A` (กันชน)
3. **`Gf` มี CKD stage ใน `[ ]`** — parse เป็น `gfr` + `ckd_stage` แยก เช่น `47[3]` → gfr=47, stage="3"
4. **วันที่แลปเก็บใน `labDates.<lab>`** (จาก `@YYMMDD`) — เอาไปโชว์ "ตรวจเมื่อ" ได้
5. **`P` มี key = ตั้งครรภ์/ให้นม; ไม่มี key = false ชัดเจน** (ไม่ต้องถามซ้ำ)

## ตรรกะ gating (ทำไมบางฟิลด์หาย)
QR ไม่ยัดทุกอย่าง — แลปแต่ละตัว**ส่งเฉพาะเมื่อ "มียาที่เกี่ยวข้อง" ใน visit นั้น + มีผลแลปจริง** (ล่าสุดตลอดกาล):
- โชว์ **O/L (ตับ)** ก็ต่อเมื่อได้ยา hepatotoxic · **G/A1 (เบาหวาน)** ต่อเมื่อได้ยา DM · **Nc/Ec** ต่อเมื่อได้ยากลุ่มนั้น · **I** ต่อเมื่อได้ warfarin · **K** ต่อเมื่อผิดปกติหรือได้ยาดัน K
- ผลลัพธ์: คนไข้ทั่วไป payload สั้น (~24-100 ตัวอักษร) · เคสยาเยอะ+แลปครบ ~223 · **ไม่เกิน 520 (QR v15)** → QR ไม่ล้น

## ตัวอย่างถอดรหัสจริง
```
N5701727|R:1000016,1000086,...|A53|SM|W64|Gf44[3]@260317|D:E109,E785,I10,...|O16@260213|L23@260213|G199@260421|A114.5@260317|Nc4262@260213|Ec381@260213
```
| อ่านว่า | |
|---|---|
| `N5701727` | HN 5701727 |
| `A53 SM W64` | อายุ 53 · ชาย · 64 กก. |
| `Gf44[3]@260317` | eGFR 44, CKD stage 3, ตรวจ 17/3/2026 |
| `O16 L23 @260213` | AST 16, ALT 23 (มียาพิษตับ) |
| `G199@260421` | FBS 199 (มียาเบาหวาน) |
| `A114.5@260317` | HbA1c 14.5% |
| `Nc4262 Ec381` | ANC 4262, AEC 381 (มียากดไขกระดูก) |

## สิ่งที่ scanner รองรับแต่ QR "ยังไม่ส่ง" (เผื่ออนาคต)
`C`=CrCl(ตรง), `Cr`=SCr, `Ab`=Albumin, `Hb`=Hb, `T`=Plt, `M`=Mg, `B`=BUN, `6`=G6PD
— ถ้าจะเพิ่มภายหลัง scanner อ่านได้ทันทีโดยไม่ต้องแก้ (แค่ QR ส่ง key พวกนี้มา)

## ⚠️ RxScreen ต้องแก้อะไร?
**ไม่ต้องแก้ parser** — `parseKeyedFields()` map ครบทุก key ข้างบนแล้ว (O/L/G/A1/Nc/Ec มี `case` อยู่จริง)
ควรตรวจแค่ว่า **rule engine / หน้าจอ ใช้ค่า `labs.ast/alt/fbs/hba1c/anc/aec` ไปเตือนจริง** (มี field แล้วต้องเอาไปใช้)
